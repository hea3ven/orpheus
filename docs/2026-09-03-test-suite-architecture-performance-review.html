Boundary check

Do not call main()

The current implementation already uses the correct in-process boundary for most command tests.

cmd/orpheus/main.go is 16 lines. It constructs cli.NewRootCommand(), executes it, prints an error, and calls os.Exit(1). Calling main() from a test would make exit handling harder and add no workflow coverage.

Keep broadly

Call NewRootCommand().Execute() in-process for complete command journeys. Supply memory state and semantic fakes so policy branches remain broad and cheap.

Keep focused

Use package units where a rule genuinely belongs to one package. Do not split broad workflows merely to make them units.

Use rarely

Run the shared test-binary helper when a child process must invoke orpheus. Keep one compiled-binary packaging smoke.

Avoid

Calling fake-backed workflows end-to-end tests, building the CLI for every case, or calling main() directly. Reserve E2E for the compiled process boundary.

Current evidence: command helpers enter an in-process Cobra root at internal/cli/helpers_test.go:458-499. Recursive fake-agent calls re-enter the test binary at internal/cli/completion_flows_e2e_test.go:711-738. Only TestIntegrationTaskRunUsesSeparateTaskProposalSelection builds cmd/orpheus, at internal/cli/task_test.go:4214-4220.
Agreed test architecture

Broad does not have to mean slow

The fast lane should protect complete behavior across packages. Real operating-system boundaries remain small and explicit.

The target is not a conventional pyramid that pushes most behavior into tiny units. Orpheus benefits from tests that cross CLI, workflow, task, state, review, and agent packages because those tests tolerate internal refactors. The cost comes from coupling that reach to real disk layouts and subprocess trees.

Package unit

One owner

Algorithms, validation, rendering, and rules that belong to a single package.

Every change

Many packages

Cobra commands through application workflows, using memory state and stateful semantic fakes.

Adapter contract

One real boundary

Focused proof against the OS filesystem, local Git, local Beads, or a controlled child executable.

Every pull request
Binary E2E

Installed shape

A compiled Orpheus process for packaging, startup, and recursive child-process behavior.

One or a few

Fake semantics, not command lines

Broad tests should configure a Git repository state, task graph, agent outcome, or pull-request result. They should not script long sequences of git status, bd show, and gh pr view responses. Raw command runners remain useful inside adapter packages, where argv translation is the contract under test.

Cobra command → application workflow → memory task and registry state → fake Git, Beads, agent, and PR capabilities → operator output and final semantic state

No generic slow-test bucket

A schedule changes when a test runs; it does not justify the test. A slow case remains only when it proves real filesystem persistence or locking, actual Git or Beads behavior, agent process supervision, compiled packaging, or a documented compatibility promise.

No compatibility promise, no compatibility matrix. Historical state schemas can usually use cheap fixtures. Multiple Git, Beads, Go, or OS versions deserve a matrix only after Orpheus declares those versions supported and a failure would lead to an actionable compatibility decision.

Quality boundary. Retain the two agreed headline values: unit coverage and integration coverage with -coverpkg=./.... Workflow, adapter contract, and binary E2E are vocabulary for source organization and review. Do not add per-kind counters, timings, thresholds, or policy fields to the routine quality report.
Enabling prerequisite

Repair the state API before migrating tests

state.Paths is a concrete struct, not an interface. Its exported contract mixes real needs with fixture convenience.

Ensure directory methods0Production callers outside state; both exported methods exist for state tests.
WriteConfigYAML53Test call sites and no production caller outside state.
ReadDataYAML76Test call sites versus two production call sites in registry and task state.
NewPaths26Test files versus one production caller outside state.

YAML belongs here. It is Orpheus' chosen application-file format, and this layer should continue to own encoding, permissions, parent creation, atomic replacement, and consistent errors. The problem is that exported roots and test-only helpers let callers bypass the abstraction or treat storage layout as workflow behavior.

Current coupling

workflow and CLI tests → state.Paths.DataPath("repos/…/tasks/…yaml") → direct YAML inspection and OS paths → test fails when storage layout changes

Many CLI tests assert workflow results by reading a hard-coded task-state filename. Those tests protect the YAML layout and the application decision at the same time.

Target contract

workflow integration → taskstate.Store.Load(repo, task) → memory-backed Paths and locks → semantic state assertion

Keep Paths concrete initially. Make roots private, remove exports that exist only for tests, and put file and mutation-lock operations behind replaceable implementations. Consumer packages can add narrow interfaces where they need them.

Fidelity rule. The memory implementation should match application-visible behavior such as missing files, malformed YAML, writes, and lock contention. OS permissions, rename failures, and platform-specific behavior remain focused real-filesystem contracts. Shared conformance tests run the supported state behavior against both implementations.

Architecture findings

What should change

Severity reflects maintenance and feedback cost, not product correctness. No live agent or network safety regression was found.

High

The quality runner disables tested concurrency

cmd/testcoverage/coverage.go:142-154 hard-codes -p=1 -parallel=1. There is no source comment explaining the restriction. The CLI suite has 239 t.Parallel() calls, and earlier project evidence measured a 47% CLI improvement from invocation-scoped parallelism.

Impact: coverage integration wall time grows from about 50 seconds to 102 seconds. Unit coverage grows from 4.44 seconds to 23.49 seconds. The quality gate then judges the sum of serialized package time rather than the delay a developer experiences.

Two package-parallel integration profiles both covered 13,654 of 20,989 statements. The current fully serialized quality result covers 13,633. The 21-statement difference is confined to internal/cli and must be understood before changing the baseline.
High

The state API exposes test fixtures as production contract

state.Paths exports roots, generic path access, directory helpers, YAML readers and writers, and the mutation-lock path. Several exports have no production consumer outside state, while broad CLI tests inspect persisted task state through hard-coded YAML paths.

Impact: tests couple workflow behavior to filenames and directories. The current struct always reaches the OS filesystem, so an isolated temporary root is safe but still slow.

Direction: keep YAML ownership in state, shrink the exported contract, make roots private, and provide replaceable file and lock implementations. Assert normal workflow state through task-state and registry APIs; use raw YAML fixtures only for persistence and migration contracts.

High

CLI integration tests carry application decision matrices on real infrastructure

internal/cli/task_test.go contains 144 integration tests and 9,510 lines, while internal/cli/task.go contains 5,277 production lines. Many tests enter the root command with fake backends, then vary blocker decisions, retry state, selection, failure injection, or rendering.

Impact: every policy case pays command construction, state setup, repository setup, and often real Git work. The breadth is useful; the infrastructure cost is not.

Direction: retain broad Cobra-to-workflow scenarios. Supply memory state and stateful semantic fakes for Git, Beads, agents, and pull requests. Use package units only where a rule has one clear package owner.

Medium

Real-Beads tests repeat an expensive fixture

Each of six adapter scenarios runs bd init in a new directory. One initialization consistently takes about 2.43 seconds and launches a large Git discovery sequence. A full package trace recorded 51 Beads invocations and 400 Git subprocesses.

Impact: the most important external contract is also the suite's critical path. Adding a new semantic case usually adds another database initialization.

Direction: organize relationship semantics as subcases inside one initialized workspace, using unique item IDs. Keep schema repair independent because it mutates the database shape.

Medium

The integration label hides three different test kinds

The tag currently covers in-process workflows, local adapter contracts, and compiled end-to-end flows. All remain part of integration coverage, but they have different costs and reasons to exist.

Impact: reviewers cannot tell whether a new integration needs a real tool, a real disk, a process, or only several packages. Cost grows when the reason for a real boundary is left implicit.

Direction: preserve the aggregate integration policy lane established by op-b20. Encode intent in file organization, test names where useful, and contributor guidance. Rely on human review rather than adding kind-aware instrumentation to the quality runner or gate.

Medium

The overlap audit cannot scale with the suite it measures

cmd/testcoverage/audit.go:89-104 launches one coverage-instrumented go test process per integration scenario. With 392 top-level tests, it repeats package TestMain setup hundreds of times. For CLI scenarios alone, the shared fixture creates Git templates before every isolated profile.

Impact: the tool needed to control integration growth becomes too expensive to run during normal test review.

Direction: add package, regex, timing-rank, and changed-test filters. Support family profiles. Run a full per-scenario audit only to answer a specific review question; do not create a standing scheduled job without a documented compatibility or audit requirement.

Recommended sequence

Fix the clock, then replace the expensive boundaries

Broad workflow coverage remains. Each migration separates application behavior from the real contract that still needs disk or a process.

01

Build on the completed op-b20 cutover

.quality.yml is now the sole quality policy. Keep its unit and integration lanes while the new work changes scheduling, test architecture, diagnostics, and reviewed bounds.

For. The later work has one stable policy contract and no legacy baseline lifecycle.
Against. The completed cutover deliberately left test execution serialized, so the current wait remains until the scheduling task lands.
02

Make quality scheduling and timing honest

With op-b20 complete, remove -p=1 while retaining -parallel=1 until the 21-statement CLI coverage difference is explained. Report developer wall time separately from summed package work and update reviewed bounds only from stable profiles.

For. Measured lane wall falls from 125.2 to about 55 seconds without deleting a test.
Against. Package contention changes timings, and wall-time policy needs stable CI hosts and wider tolerance.
03

Refactor state.Paths and prove memory-backed state

Shrink the exported contract, keep YAML behavior, make roots private, and route files and mutation locking through replaceable implementations. Run shared behavior tests against memory and the OS, then execute one existing broad command journey entirely on memory state.

For. Removes disk from workflow tests without discarding YAML or rewriting every consumer around a broad interface.
Against. Direct root access and raw YAML assertions are widespread, so the migration must prevent new bypasses while preserving real persistence contracts.
04

Compose a complete fake-backed application

Let the Cobra root receive memory state plus semantic Git, task-backend, agent, and pull-request capabilities. Fakes hold meaningful state and outcomes; they do not emulate raw command sequences. Keep low-level runners inside adapter tests.

For. Preserves command-to-workflow reach and makes internal package moves cheap for tests.
Against. Stateful fakes are production-like code that needs shared contracts and concurrency-safe behavior.
05

Migrate expensive workflow families without narrowing them

Move task dispatch, review and repair, finalization, synchronization, repository registration, and status scenarios one family at a time. For each old real-infrastructure test, preserve application assertions in the broad workflow test and preserve only the necessary OS or tool assertion in an adapter contract.

For. Reduces process and disk cost while retaining the refactor protection the broad tests provide.
Against. Coverage overlap cannot prove equivalence. Every removal needs an assertion map and measured before-and-after evidence.
06

Consolidate real adapter contracts

Initialize one Beads relationship workspace for cross-type, related-edge, cycle, pre-mutation, and create-with-dependency subcases. Keep schema repair separate. Retain the focused real-Git matrix and review it only for duplicated setup, not for arbitrary count reduction.

For. The Beads change alone can remove about 9.7 seconds of repeated initialization.
Against. Shared fixtures can become order-dependent. Use unique identities, explicit postconditions, and shuffled validation where practical.
07

Reserve E2E for the process boundary

Keep the in-process Cobra root for broad workflows. Retain one compiled packaging smoke and the shared test-binary helper only where Orpheus must supervise or recursively invoke a child process. Do not call main() directly.

For. Makes the term E2E meaningful and prevents routine workflow variants from rebuilding or relaunching the CLI.
Against. A very small binary suite relies on adapter and workflow contracts being explicit and complete.
08

Classify and curate integration tests by boundary

Keep unit and integration as the reviewed policy lanes. Document workflow, adapter-contract, and binary-E2E tests as source and review categories. Make the existing on-demand overlap audit selectable by package and test regex, but do not add kind-aware instrumentation to routine quality or CI.

For. Reviewers get a clear language for challenging expensive boundaries, and they can narrow an audit without complicating the gate.
Against. Classification can drift because human review, rather than automation, enforces it. That is a reasonable cost until drift becomes an observed problem.
